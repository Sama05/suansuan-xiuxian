# 算力修仙

放置类数值游戏。以算力入道，以设备筑基。

## 快速开始

```bash
npm install
npm start          # 启动服务，默认 http://localhost:3210
```

> 需要 Node ≥ 18（`better-sqlite3` 是原生模块，首次安装会编译，Windows 上可能需要 VS Build Tools）。

浏览器打开 `http://localhost:3210`，注册账号即可开玩。

```bash
npm test           # 运行全部测试（2326 项）
```

> 想在测试里跑端到端用例，需先 `npm start` 另开一个终端。未启动时该套件会自动跳过。

## 玩法

八个子页面，从顶栏切换：

| 页面 | 内容 |
|------|------|
| **境界** | 当前境界、突破进度、时间速率档位、神识与灵气产出倍率 |
| **工作** | 精力条 + 当前工作 + 工作列表（前期主要的赚钱手段） |
| **设备** | 购买算力设备；后 5 台是「修仙 × 科技」，双造价（金钱 + 灵石）并增幅神识 |
| **投向** | 把算力分配到五条路线，含「功法增幅」 |
| **功法** | 未习得前为锁定占位；习得后显示当前修炼、熟练度、功法阁、常驻被动、神识面板 |
| **公司** | 未注册前为锁定占位；注册后显示经营概览、仓库、工业算力、生产线（每台可换产物/调产能） |
| **市场** | 独立页面；按行业分组展示 72 种商品的行情、走势、抛压与库存操作（未成立公司也能看价） |
| **股市** | 未开户前为锁定占位；开户后显示账户概览、行情时钟、市值前 10 榜单（可展开全部 50 家）与买卖 |

核心循环：

```
工作（消耗精力）→ 金钱 / 灵气 / 灵石
     ↳ 买算力设备 → 算力 → 分配到 修仙 / AI / 计算设备 / 金融 / 功法增幅
     ↳ 买下第一台个人电脑 → 获得第一本功法 → 解锁 功法 / 神识 / 灵气 三个系统
     ↳ 修炼功法（涨熟练度）→ 灵气吸收速度 ↑  → 灵气 → 突破境界
     ↳ 境界提升 → 更快的时间档位 + 更高的精力上限 + 更高阶工作 + 更高基础神识
     ↳ 注册公司（炼气 + 5 万）→ 买生产线 → 拨工业算力 → 每台线选产物/调产能 → 每 20 秒一个生产周期
          → 产物入库 → 按市价卖出 → 金钱（不消耗精力，但与时间档位无关）
     ↳ 开户（炼气）→ 买卖五只股票 → 赌自然价方向赚差价，但自己的买卖会反压成交价
```

### 两种货币 + 两个属性

改数值前务必分清这四个东西，`game-config.js` 顶部也重复了一遍：

| 名称 | 定位 |
|------|------|
| **金钱** money | 买算力设备。来源：工作 + 设备被动收益 + 投向「金融行业」 |
| **灵气** qi | **突破境界的唯一货币**。必须先习得功法才会产生 |
| **灵石** spiritStone | **后期修仙类资源**，用于购买「修仙 × 科技」设备（金钱 + 灵石双造价） |
| **算力** compute | 设备提供，投向五个方向 |
| **神识** shenshi | 一开始就有，随境界成长、被设备增幅。**同时**放大「实际算力的效果」与「功法修炼速度（= 灵气提升速度）」 |

> 早期版本把「灵石」同时当作突破资源。v2 拆分：突破资源改名为**灵气**，灵石独立为后期购买力。旧存档读取时会自动把旧的 `spiritStone` 迁移到 `qi`。

### 时间系统

所有玩家都从 **2000 年** 起步。游戏内时间按「速率档位」推进，档位越高，同样的现实时间在游戏里走得更远，工作完成得越快：

| 档位 | 名称 | 速率 | 解锁境界 |
|------|------|------|----------|
| 1 | 缓 | 1 秒 = 10 分钟 | 凡人 |
| 2 | 常 | 1 秒 = 1 小时 | 炼气 |
| 3 | 疾 | 1 秒 = 1 天 | 筑基 |
| 4 | 倏 | 1 秒 = 1 月 | 金丹 |

默认自动跟随已解锁的最高档位；也可以在「境界」页手动锁档。顶栏随时显示游戏内日期。

> 设计意图：**境界越高，光阴越快**。越往后的工作耗时（游戏内时长）越长，但配合更快的档位，玩家感知到「做完一份工作」的现实时间大致恒定（约 10–30 秒）。

### 工作系统

工作全程都是金钱的主要来源。当前收录 15 份基于现实职业的工作，按「解锁境界 + 前置工作完成次数」逐级放开，形成升职感：

```
街头发传单 → 便利店店员 → 外卖骑手 → 网约车司机 → 物流分拣中心
  → 工地塔吊操作员 → 初级程序员 → 注册会计师 → 三甲医院主治医师
    → 律所合伙人 → 上市公司高管 → 创业公司 CEO
      → 灵矿勘探开采工程 → 洞天福地基建工程 → 灵脉算力网络建设
```

前 12 份是纯现实职业；后 3 份是**修仙 × 科技**的融合岗位，会同时产出**金钱 + 灵气 + 灵石**。每一项都严格遵守单调性：层级越高，工作耗时越长、单次精力消耗越大、金钱/小时越高、金钱/精力也越高（不会出现「高级工作更亏」）。

**精力**：上限随境界提升（凡人 100 → 元婴 660）。按**现实时间**每秒 +1 恢复，与现实时间绑定、不受速率档位影响 —— 这是刻意的，精力是产能的硬上限，否则玩家把时间档位拉满就能无限产出。精力不足时工作会停在原地等恢复，**进度不丢失**。

**两种推进方式**：

- **自动**：开启「自动工作」后按循环自动完成当前工作，离线也照常结算
- **手动催工**：点「催工」立即完成一次（快捷键：数字键或空格），消耗同样的精力

### 设备系统

10 台设备，分两类：

**纯科技（5 台，金钱买）**：个人电脑 → 工作站 → 大型集群 → 数据中心 → 超大数据中心集群。
`costGrowth` 逐台变陡（1.10 → 1.18），单台算力跨数量级跃升。

**修仙 × 科技（5 台，金钱 + 灵石双造价）**：

| 设备 | 算力 | 神识增幅/台 | 灵石产出/秒 | 灵石造价 |
|------|------|------------|------------|----------|
| 灵石供电机柜 | 5e8 | +0.5 | 5 | 2e3 |
| 灵脉直连阵列 | 5e10 | +2 | 40 | 5e4 |
| 阵法加速节点 | 5e12 | +8 | 400 | 1.5e6 |
| 洞天算力中心 | 5e14 | +30 | 5,000 | 5e7 |
| 太虚晶格超算 | 5e16 | +120 | 80,000 | 2e9 |

> 用户要求「后期设备对神识的增幅更高，尤其是科技修仙设备」—— 所以后 5 台的 `shenshiBonus` 是数量级跃升（0.5 → 2 → 8 → 30 → 120），并且它们自己能产灵石，让灵石经济可以自我滚动。

### 金钱来源

| 来源 | 定位 |
|------|------|
| 工作 | 前中期主力，跨数量级增长 |
| 设备被动收益 | 后期底盘，稳定但不暴涨（`base.autoIncomePerCompute` 刻意压低） |
| 投向「金融行业」 | 短线变现，换取买设备的本金 |
| **公司卖出商品** | 中后期主力（见「公司系统」）。不消耗精力，但与时间档位无关 |

> 后期金钱消耗会显著变大，单靠工作不够 —— 这正是公司系统存在的意义：它把「金钱」从「拿时间换」变成「拿资本与判断换」。

### 投向路线

五条路线相互强化，不是互相替代：

| 路线 | 作用 | 定位 |
|------|------|------|
| 修仙方向 | 灵气（境界）的核心来源 | 主线 |
| AI 领域 | 产出转化为算力增量，放大所有路线 | 中线 |
| 计算设备领域 | 压低设备造价 | 中线 |
| 金融行业 | 直接变现，换取买设备的本金 | 短线 |
| 功法增幅 | 习得功法后解锁，产出作为**灵气倍率**叠加（+30%/满额） | 需先习得功法 |

分配比例之和不超过 100%。**修仙为 0% 且功法增幅为 0% 时灵气不会增长，境界无法推进**。未解锁的「功法增幅」不参与分配，它的份额会自动让给修仙。

### 功法系统

**获取链**：买下第一台**个人电脑** → 自动习得第一本功法（黄级「九章算经·残卷」）→ **同时解锁功法系统、神识系统、灵气系统**（在此之前灵气恒为 0）。之后每本功法按「境界 + 算力」条件自动习得。

**同一时间只能修炼一本**，可在「功法」页切换。

**命名规则**：数学的深奥程度 × 修仙术语。数学越深入，稀有度越高。

| 功法 | 门类 | 稀有度 | 主属性基值 | 被动属性 | 解锁条件 |
|------|------|--------|-----------|----------|----------|
| 九章算经·残卷 | 算术 | 黄 | ×0.20 | 工作金钱 +5% | 个人电脑 ×1 |
| 代数真解 | 代数与几何 | 玄 | ×0.60 | 精力上限 +10% | 炼气 |
| 流数周天 | 微积分与分析 | 地 | ×1.8 | 算力 +10% | 筑基 |
| 流形遁法 | 拓扑与流形 | 天 | ×5.0 | 设备成本 −15% | 金丹 |
| 同调大衍篇 | 范畴论与同调代数 | 宇 | ×15 | 神识 +25% | 元婴 + 算力 1e6 |
| 连续统真言 | 数理逻辑·大基数 | 宙 | ×45 | 全部产出 +30% | 元婴 + 算力 1e9 |

**稀有度**：6 级，取自「天地玄黄，宇宙洪荒」前六字 —— 黄 → 玄 → 地 → 天 → 宇 → 宙。稀有度**无法提升**，越高主属性基值越强（0.2 → 0.6 → 1.8 → 5 → 15 → 45）。

**等级**：`level = floor(log10(1 + 算力) × 4)`，由**算力**换算，**无上限**。每级提升主属性 8%，所以等级越高，灵气吸收速度越快。

**主属性通项**：`灵气吸收加成 = 稀有度基值 × (1 + 等级 × 0.08)`，直接乘进灵气产出。

**熟练度**：6 段 —— 入门 / 熟练 / 小成 / 精通 / 大成 / 圆满（累计熟练度 0 / 60 / 240 / 900 / 3000 / 9000）。

- **修炼**：挂机自动积累熟练度，速度 = `1 × (1 + 神识 × 0.02)` 点/现实秒
- **参悟**：消耗灵气（当前境界突破需求的 2%），立即获得一笔熟练度（相当于熟练度的「催工」）
- **被动转常驻**：熟练度修满（圆满）后该功法的**被动属性转为常驻**，之后切换到别的功法也不会丢失

> 存档里功法的三件事分开存：`mastery`（进度）/ `tier`（段位）/ `passive`（被动是否常驻）。兵解（见「待建设」）要用到这三者的差异：**保留功法、清空等级、清空熟练度进度、保留熟练度段位**。

### 神识系统

神识**一开始就有**（凡人基础 1），不属于「习得功法才解锁」的范畴 —— 解锁的是灵气与功法页。它的总量：

```
神识 = 境界基础神识 × 设备倍率 × (1 + 功法被动加成)
      凡人 1 → 炼气 4 → 筑基 14 → 金丹 40 → 元婴 100
      设备倍率 = 1 + Σ(设备.shenshiBonus × 持有数)
```

它同时作用于两处：

- **放大实际算力**：`实际算力 = (设备算力 + AI 加成) × (1 + 神识 × 0.02) × (1 + 功法被动算力加成)`
- **放大功法修炼速度**：`修炼速度 = 1 × (1 + 神识 × 0.02)`，而修炼速度就是灵气提升速度

### 公司系统（产业）

**公司不是「更好的工作」，而是一条独立的经济线。**

| | 工作（职业） | 公司（产业） |
|---|---|---|
| 本质 | 别人雇你，你出卖时间 | 你自己造商品、自己卖 |
| 收益 | 固定（配置死） | 随**市价**浮动 |
| 消耗 | 精力 | 精力外的**维护费**（按所选产物计） |
| 推进 | 游戏内时间（受档位加速） | **现实时间**（20 秒 / 周期，与档位无关） |
| 瓶颈 | 精力上限 | 工业算力 + 仓库容量 + 现金流 + 择时 |
| 尺度 | 单次收益随境界跨数量级暴涨 | 靠**规模**（多买生产线）与**算力配置**取胜 |

关键设计是最后两行：生产周期挂在**现实时间**上，所以把时间档位拉满**不会**让公司多产一分钱。公司要赚得多，只能多买线、并给够工业算力；价格好时手动卖货。

**注册**：炼气期 + 5 万金钱。注册后才有资格买生产线。

**每周期三步**（顺序不能打乱）：

1. **扣维护费**（按当前每台线的产物与产能计费）。钱不够 → 本周期**停产**，但不欠费（不会扣成负数）
2. **各生产线按实际产能产出入库**。仓库满 → 超出部分**直接放弃**，形成经营压力
3. **自动卖出**（可关）。开着就按当前市价清仓

**生产线（12 类，每类 ≥6 种产物）**

新版本把「固定产物」改成「买下一条产线后，**每一台都能自由选择产物与产能**」：

- 每条线有一个固定的**行业**和**算力上限**（如矿井：采掘行业、4000 算力 / 台）
- 一条线能造的全部产物 = 该行业的 6 种商品（如采掘：铁矿石、焦煤、铜矿石、铝土矿、硅石、稀土矿）
- 每台线独立配置：产物下拉 + 产能拖动条（0%–100%）+ 全部套用按钮
- 产量 = 线基准产量 × 产物系数 × 产能 × 算力削减系数
- 维护费 = 所选产物 × 当前价 × upkeep 费率 × 产能

科技线：矿井 → 炼钢厂 / 化工厂 → 精密制造厂 → 电子元件厂 → 整机装配厂。
修仙线：灵田 → 符箓工坊 / 丹房 → 炼器坊 → 阵盘锻造坊 → 洞天营造司。

**工业算力**：

- 买线只拿到「产能上限」，真正转起来要靠**「工业产能」这一投向**
- 工业算力 = 设备总算力 × 你拨给「工业产能」的份额
- 全厂算力需求 = Σ(每条线 maxCompute × 该台产能)
- 供给 < 需求时，**全厂按比例削减**（不是先到先得）；所以多买线不会凭空增产，只会把每条线摊薄
- 界面提供「工业算力」面板：实时显示供给 / 需求 / 削减比例 / 份额，不足时一键跳到「投向」页

**行业与成本传导**：

- 12 个行业组成上下游 DAG：采掘 → 冶炼/化工 → 精密/电子 → 整机；灵植 → 制符/炼丹 → 炼器 → 阵盘 → 洞天；修仙线与部分科技线也互相喂（如炼器需要金属）
- 上游商品价格涨跌会顺着产业链传导：
  - **成本指数** = 上游价格 × `passThrough`（一般 0.5 左右）→ 下游成本涨得快
  - **售价指数** = 上游价格 × `pricePass`（一般 0.25–0.32）→ 下游售价跟涨得慢
  - 结果：上游涨价会压缩下游毛利，玩家能直观看到「矿价涨了，钢厂毛利掉了」
- 行业景气面板把每个行业的「成本指数 / 售价指数 / 上游价格水平」实时列出来

**仓库**：基础 500 件，每级 +600，共 40 级（满级 24500 件）。升级价按 ×1.55 递增。仓库是公司唯一的「软上限」，压货久了就白干。

**市场（确定性价格）**：市价**不用随机数**。**自然价**由 `(商品序号, 期数)` 喂进一个散列函数推导 —— 同一个输入永远得到同一个价格。这一点是硬约束：前端每 100ms tick 一次、后端离线一次性结算 48 小时，两边必须算出**完全相同**的价格，否则「屏幕上看到的钱」和「服务器存的钱」会对不上。实际成交价 = 自然价 × 行业售价指数 × 抛压修正（没有抛压且上游平价时两者相等）。

- 第 0 期 = 开市，直接按配置里的 `basePrice` 挂牌
- **科技类逐年变价**（`periodYears: 1`），**修仙类每 10 年变价**（`periodYears: 10`）
- 涨跌标记沿用中国习惯：**涨红 / 跌绿**（`.trend.up` → `--red`，`.trend.down` → `--jade`）
- 市场已从公司页**独立成一个页面**，按行业分组展示 72 种商品；未成立公司也能看行情，但卖货需要公司

**价格走势图**：市场页顶部是当前选中商品的走势折线，每个商品行里还有一条迷你走势；点商品行即可把大图切过去。画法与公司页相同：实线已发生 / 虚线推演 / 灰点线基准价，有抛压时叠一条自然价参考线；约束仍是不使用 `<circle>`、描边带 `vector-effect`。

**离线**：公司照常生产（`offline.companyWhileOffline`），但同样按 30% 效率折算、同样受维护费约束，所以不会比在线更赚。

**市场抛压（卖出反噬）**：规则是「**卖超产才会被压价**」：

- 每期分别记账 `soldThisPeriod`（本期货卖出的件数）与 `producedThisPeriod`（本期入库的件数）
- 到了**期数边界**结算一次，抛压增量：
  ```
  超额 = max(0, 卖出/期数 − 产出/期数)
  抛压增量 = 超额 / max(baseVolume, 产出/期数)
  新旧抛压 = 旧抛压 × 0.5^跨越期数 + 增量（再夹到 [0, 1]）
  ```
- **正常经营（自动卖出 = 产能）→ 超额为 0 → 抛压恒为 0**。只有**囤货砸盘**才会被压价
- 当前期的成交价 = `自然价 × 行业指数 × (1 − 抛压 × maxDrop)`；综合价另有绝对下限 `floor=0.15`
- 结算在 `stepTick` 里排在 `syncCompany` **之前**，保证「本期卖出的货」影响的是**下一期**的价格

前端配套：每个商品行多一条**抛压条**；走势图叠自然价参考线；市场页顶部汇总「抛压最高 X%」。数据侧：`pressure / soldThisPeriod / producedThisPeriod / lastPeriod` 随存档走；`hydrate` 夹范围，`lastPeriod` 夹到不超过当前期；后端 `/api/save` 把 `pressure` 夹到 `[0,1]`。

### 股市系统（证券账户）

**股市不是「无风险的被动收入」，而是一个零和的赌局 —— 唯一稳定的收益来源是「赌对自然价的方向」。**

公司与股市的关系：公司是「自己生产、自己卖」，股市是「买卖别人手上的公司」。股价用**确定性函数**，并额外承受**你自己的持仓冲击**；同时每只股票下面都显示 **主营业务**，行情一动就能看出波及哪些公司。

| | 公司（产业） | 股市（证券） |
|---|---|---|
| 本质 | 造商品、按市价卖 | 赌别人公司的股价波动 |
| 你的作用力 | 卖超产 → 压下一期价 | 买入推高 / 卖出压低**当前成交价** |
| 收益来源 | 产能 × 净收益率 | 自然价的方向（低买高卖） |
| 稳态收益 | 正 | **零和**；随手一轮买卖必亏（溢价 + 双边手续费） |
| 尺度 | 靠规模（多买线）与算力 | 靠本金（后期资金越大，单笔冲击越大） |

**开户**：炼气期。不另收开户费。

**上市公司池：50 家，界面只列市值前 10**

- 30 家科技 + 20 家修仙宗门，每家都有 `business`（主营业务），股市页每行直接显示
- 行情页默认只展示**市值前 10**（`boardSize=10`），榜单随行情换人；点「显示全部 50 家」可展开完整池子
- 交易对全部 50 家开放 —— 接口按 `id` 找，榜外公司照样能买，为后续「收购 / 退市」留玩法

**三层价格**：

```
成交价 = 自然价 × 冲击系数
自然价 = 基准价 × 行情波动因子 × 行业联动因子
```

1. **行情波动因子**：`exp(volatility × k)`，`k = hash01(股票序号, 期数)` 映射到 `[−1, 1]`。**不用随机数**。`volatility` 越大摆动越凶。
2. **行业联动因子**：`1 + (关联商品价格倍数 − 1) × linkWeight`。公司商品属于某个行业，该行业的整体售价指数（含成本传导）会联动到挂钩股票；`linkWeight=0.5` 是刻意的**半联动**。
3. **冲击系数（反作用）**：`1 + 净流入 / 流通盘 × maxRise或maxDrop × (1 + 持仓集中度 × illiquidity)`。买得越多推得越高（`maxRise=0.60`），砸得越狠压得越低（`maxDrop=0.50`）。

**核心机制：成交按「成交之后」的冲击价结算。** 买入的那一瞬间就把价格顶高了，所以成交均价**高于**下单前市价；卖出同理。这就是「一轮买卖必亏」的根源。

- 净买入流**逐期衰减**（`flowDecay=0.5`，一期减半）。你买出来的溢价会随时间消退，**等它涨回去再卖拿不到那个溢价**。
- **持仓集中度放大冲击，但不抬高价格水平**；否则就是无风险套利。
- **手续费双边收**（`fee=0.005`），且设**最小成交额**（`minOrder=1e4`）。
- 成交价另有绝对下限 `floor=0.05`。

**账户概览**：

- **浮动盈亏** = `市值 − 持仓成本（含费）`。市值按当前成交价计 —— 看着好看，但卖不掉。
- **可变现盈亏** = `清仓报价（把你自己的砸盘算进去）− 持仓成本`。点「全部卖出」实际能拿到的钱，通常**明显小于**浮动盈亏。

**结算在 `stepTick` 里排在 `syncCompany` 之后**（第 9c 步，公司抛压结算之后）—— 这样联动因子读到的是**本期已结算完**的商品售价指数。

**前端**：锁定占位页讲清机制；开户后是「证券账户概览 + 行情时钟 + 走势大图 + 行情列表（默认前十，可展开全部）」。每行显示**主营业务**，带冲击条、持仓、浮动盈亏和买卖面板。

**离线**：股市**不在离线结算范围内** —— 它挂在「期数」上，离线期间行情照走，但没有买卖动作。

**数据侧**：`s.stock = { shares, flow, cost, lastPeriod, realized, totalFee, totalTrades }` 随存档走；`hydrate` 逐项夹范围；后端 `/api/save` 对 `shares / flow` 夹范围、`cost` 负值归零，`realized / totalFee / totalTrades` 只增不减。配置见 `game-config.js` 的 `stock` 段。

| 凡人 | 起始 | 2000-01-01 |

### 校准观察（留给下一轮调优）

跑 `sim.js` 发现的三件事，都属于「需要更多内容才能定」的问题，先记下来：

1. **各流派收敛**：`even`（均衡）反而最快（元婴 9.2h），`xiuxian`（全压灵气）最慢（11.9h）。说明真正的瓶颈是**算力**而不是分配比例 —— 这符合设计意图（动态调配优于一路走到底），但也意味着境界阈值 ×100 的曲线被灵气收入的增长正好抵消，导致 炼气之后每级都稳定在 3–4 小时，缺少减速感。想让后期更慢，应调 `realms[].need` 而不是调投向。
2. **神识是自激回路**：神识放大算力 → 算力产钱 → 钱买设备 → 设备加神识。72 小时实测神识 5.4 万（设备倍率 429），实际算力 / 原始算力 = ×1182，灵气倍率 ×43 万（境界阈值此时早已被溢出几个数量级）。因为元婴是当前版本最后一境，溢出暂时无害；但加入更多境界/公司/市场前，需要给这条回路加阻尼（例如神识对算力的加成改成次线性 `^0.5`，或改成加法而非乘法）。
3. **最后一台修仙设备够不到**：「太虚晶格超算」需 2e9 灵石，而玩家在买前面的「洞天算力中心」（5e7 起、×1.26 递增）时会把灵石池持续抽干 —— 贪婪买法跑满 168 小时也买不到它。要么给灵石开新来源，要么调整后两台的灵石造价阶梯。

## 技术选型说明

### 大数方案：十进制浮点

放置类游戏后期数值会突破 JS `Number` 的 1.8e308 上限，`BigInt` 又无法表示小数。因此自建十进制浮点数：

```
value = sign × mantissa × 10^exponent
mantissa 归一化到 [1, 10)，清洗到 14 位有效数字
```

与 Antimatter Dimensions、Cookie Clicker 等成熟作品采用同一思路，上限约 1e(9e15)，远超游戏需求。溢出时饱和而不是归零。

> 清洗位比 JS `double` 的可靠精度（约 15 位）**低一位**是有意的。按 15 位清洗会把最后一位的浮点噪声当成有效数字留下 —— 例如 `new D(480).add(new D(240))` 会得到 `7.199999999999999e2` 而不是 `7.2e2`（因为 `4.8 + 2.4` 在二进制下不精确）。这类「整数相加得到非整数」的脏值会让 `eq` 比较失效，存档里也会出现长尾巴。留 1 位保护位即可抹掉噪声，而 14 位有效数字对放置类游戏绰绰有余。

### 三条时间线

`tick()` 内部同时维护三条互不干扰的计时：

| 时间线 | 驱动方式 | 作用 |
|--------|----------|------|
| 游戏内时间 | 速率档位（1 秒 = 10 分钟 ~ 1 月） | 推进工作进度、顶栏日期、商品变价周期 |
| 现实时间 | 真实经过的秒数 | 设备被动收益、算力投向产出、灵石产出、修炼、精力恢复、**公司生产周期** |
| 精力 | 现实时间，固定 +1/s | 产能硬上限，与档位解耦 |

`stepTick()` 的固定顺序（改逻辑时不要打乱）：游戏时间 → 精力 → 神识/实际算力 → **功法习得检查** → 工作结算 → 设备被动收益 → 灵石产出 → 投向产出 → **公司周期** → 修炼涨熟练度 → 硬件折扣 → 境界突破（消耗灵气）→ 自动档位。

> 「功法习得检查」放在工作结算之前很关键：买到个人电脑的那一瞬间，本段 tick 就应该已经能产灵气，而不是等下一段。

> 「公司周期」跟精力一样挂在现实时间上，所以它是一条**与档位解耦的产能上限**：拉满档位只会让工作更强，不会让公司多产一分钱。

### 顶栏为什么不抖

顶栏资源条最早是 `flex: 1` + `flex-wrap: wrap`，结果出现了「资源条来回跳动 / 自己折叠」——根因是**每个 `.res` 的宽度由内容撑开**：副标题每 100ms 就会在「设备提供」和「设备 1.2万 + AI 3千」之间变长变短，宽度一抖就可能跨过 flex 的换行阈值，整组折到第二行，顶栏变高，下面所有内容跟着上下跳一次。

改法是让列宽**与内容完全无关**：

```css
.res-group {
  display: grid;                                  /* 不再用 flex + wrap */
  grid-template-columns: repeat(6, minmax(0, 1fr));
}
```

grid 的列宽只由容器宽度决定，数值再长再短都不会重排；窄屏用媒体查询把列数降到 3 / 2，但仍是**固定列数**。配套还有三处细节：

- `.res .k / .v / .sub` 单行截断（`nowrap` + `ellipsis`），内容再长也撑不宽所在列；`.sub` 给 `min-height`，避免空文本时顶栏塌一格
- 数值统一 `font-variant-numeric: tabular-nums`（等宽数字）；时钟和用户名限宽，日期位数变化（9月9日 → 10月10日）不再左右推挤
- 渲染层加了 `setText(id, value)` 值缓存：**文本没变就不碰 DOM**。`renderTop` 每 100ms 跑一次，无条件重写 `textContent` 会让浏览器反复做「replace data → 重新测量文本宽度 → 重排」

`tests/frontend.test.js` 的「顶栏布局稳定性」小节把这些都钉住了，包括一条反向断言：`.res-group` 里**不允许再出现 `flex-wrap`**。

### 前后端同一份 tick

`shared/game-core.js` 的 `tick()` 同时被前端（100ms 实时刷新）和后端（离线结算）调用。两端算法完全一致，因此不会出现「屏幕上显示的进度」与「服务器保存的进度」对不上。

离线结算按 60 秒为一段循环推进（`STEP_REAL_SECONDS`），避免一次性大步长导致的工作进度/精力判定失真。

### 服务端权威

`/api/action` 走服务端校验：`setJob` / `setWorking` / `rushJob` / `setTimeTier` / `setAutoTier` / `buyDevice` / `setAllocation` / `setTechnique` / `setCultivating` / `comprehend` / `foundCompany` / `buyLine` / `upgradeWarehouse` / `sellGoods` / `setAutoSell` / `buyStock` / `sellStock`。

其中 `buyStock` / `sellStock` 一律**服务端按自己的报价成交** —— 客户端只提交 `stockId` 与股数，成交均价、手续费、冲击系数全部由服务端重算，返回 `unitPrice / gross / fee / net / impact / sharesAfter` 供前端对账。

`/api/save` 做防作弊，以下字段每个 key **只允许增加**，不允许回退：

```
playTime · realm · gameSeconds · totalJobs · rushCount · jobDone[各工作] · devices
learned[各功法].mastery / .tier / .passive   ← 功法进度同样只增不减
company.founded / .foundedDay / .warehouseLevel / .cycles
company.lines[各生产线] · company.goodsSold[各商品]
company.totalRevenue · company.totalUpkeep
stock.realized / .totalFee / .totalTrades   ← 股市盈亏与成交笔数同样只增不减
```

另外 `learned` 里的键**不允许被整条删除**（清空即拒绝），`technique` 也不允许被清空 —— 否则客户端可以把功法「退掉」再重新触发一次获取。

公司还有一条专门的单向门：**`founded` 只能由服务端点亮**。客户端提交 `founded: true` 但服务端记录里从没成立过 → 直接改回 `false`（否则等于零成本开公司）。

和金钱、设备数量同一档的字段（`money` / `company.stock` / `stock.shares`）**不做只增保护** —— 它们本来就会在卖出与消费时减少。库存的替代约束是**容量上限**（`hydrate` 把超容库存裁到当前仓库容量内）；股市持仓的替代约束是**流通盘上限**（`shares / flow` 各自夹到 `[−流通盘, 流通盘]`）。

客户端只负责展示与实时手感。

## 离线收益

- 离开 < 60 秒：视为「短暂离开」（刷新页面、切标签页），**全额结算**，不打折
- 离开 ≥ 60 秒：按 **30% 效率**折算，最多累计 **48 小时**
- 离线期间**工作照常推进**、**功法照常修炼**、**公司照常生产**（`offline.workWhileOffline` / `cultivateWhileOffline` / `companyWhileOffline`），但精力按现实时间恢复、公司按现实时间走生产周期，因此离线产出同样受精力上限与维护费约束
- **股市不参与离线结算**：它靠买卖动作产生盈亏，人不在场就既没有成交也没有冲击。离线期间行情照走（确定性能算出来），但你的持仓价值变化不落进离线收益汇总

阈值与比例都在 `shared/game-config.js` 的 `offline` 段。

## 调数值

所有数值集中在 `shared/game-config.js`，改完用模拟器验证：

```bash
node tools/sim.js 72            # 模拟 72 小时，输出境界/功法/设备时间线
node tools/sim.js 72 xiuxian 5  # 指定策略 + 步长（秒）
node tools/sim.js 72 even       # 均衡分配
node tools/sim.js 72 finance    # 金融优先
node tools/sim.js 168           # 拉长到一周，检查后期设备是否够得到
```

模拟器扮演一个正常玩家（挑金钱/现实秒最高的工作、有钱就买性价比最高的设备、习得功法后切到主属性最强的那本修炼），用来检查进度曲线是否合理，避免出现「后期几小时暴涨」或「中期永久卡死」。

生成演示账号（跑完模拟后直接写库）：

```bash
node tools/seed-demo.js <用户名> <密码> [模拟小时数]
```

> 注意 `base.incomeExponent` 这个指数：调大**不会**让游戏更难，反而会让后期收益二次复合，几分钟内资金暴涨、境界连跳。想知道当前取值的由来，看 `game-config.js` 里的注释。
